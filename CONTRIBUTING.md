## How to contribute
All contributes are welcome of all kinds. All bug fixes, and documentation fixes are appreciated and new feature proposals are encouraged. 
1. **Fork** the repository and create your branch from `main`.
```bash
   git checkout -b feature/your-feature-name
```
2. Make your changes, following the code style and testing guidelines below.
3. Commit your changes with a clear, descriptive message.
```bash
   git commit -m "Add: scoring bonus for perfect rounds"
```
4. Push to your fork and open a **Pull Request** against `main`.
5. Fill out the PR template, describing what you changed and why.
6. A maintainer will review your PR, request changes if needed, and merge once approved.
## Code style or formatting guidelines
- Follow the existing code style used throughout the project.
- Use consistent indentation (match the surrounding file).
- Keep functions small and focused on a single responsibility.
- Use descriptive variable and function names 
## Testing requirements
- Add or update tests for any new feature or bug fix.
- Ensure all existing tests pass before submitting a PR:
## Documentation standards
- Update the `README.md` if your change affects installation, usage, or gameplay behavior.
- Use clear, concise language.
- If you add a new category pack or config option, document how to use it.
## How to report bugs
- Search the eixisting issues first to avoid duplicates.
- Open a new issue using the **Bug Report** template 
- Include:
  - Steps to reproduce
  - Expected vs. actual behavior
## How to propose new features
- Search the eixisting issues first to avoid duplicates.
- Open a new issue using the **Feature Proposal** template 
- Include:
  - describe the proposed feature and the problem it solves
  - Describe what the end result should be if there feature is accept
## Community guidelines and expectations
- Be respectful and constructive in all interactions
- Assume good intent; ask clarifying questions before assuming a change is wrong.
